Ledger · Design system

The parts this site is built from.

Every token, type step and component state used across the portfolio and the blog. Poppins for names and titles, Roboto for everything you scan, JetBrains Mono for anything countable. Monochrome throughout: no hue carries meaning, so hierarchy comes from weight, size and a single background step. Dark is the default; every token has a light counterpart and the rail switches between them.

Rules of the page

08 · Media

Two tiers · portrait first

Photographs are the one place this system meets colour, so the treatment depends on the job the image is doing. Interface photography converts to grayscale and returns to colour on hover. Photography that carries evidence stays in full colour inside a frame.

Everything shot on a phone is portrait, so portrait is the default orientation. Landscape is reserved for screenshots and diagrams, which are landscape by nature. A portrait photograph is never cropped to a banner.

Which tier

01  Does the photograph prove something? Full colour, framed, captioned.

02  Is it interface, a portrait or a thumbnail? Grayscale, colour on hover.

03  Is it atmosphere? Grayscale, unframed, and only where a page needs air.

04  Personal photographs live on About and Now. Never inside a case study.

Crop

Figures use the 3:4 frame as shot, with no crop at all. A circular portrait cannot be reached with object-fit when the subject sits off to one side, so the image is scaled inside the circle and offset until the face lands on the centre.

10 · Article

Blog post in situ
14 March 2026 · 8 min · Architecture

Clean architecture in a government codebase

What survives contact with a ten-year-old Oracle schema, and what you quietly give up.

The schema is the contract

Every layered-architecture diagram assumes you own the data model. In a system that has been running since before you arrived, you do not. The schema is the contract, and the domain has to be reconstructed around it rather than derived from it.

The pragmatic version keeps the boundary at the repository and lets Entity Framework map to views instead of tables. Reads go through projections, writes go through stored procedures that already encode two years of business rules nobody documented.

Where the boundary lands

What it buys you

  • The domain type never sees an Oracle column name.
  • The view absorbs schema drift; the mapping is the only thing that changes.
  • Integration tests run against a real Oracle container, not an in-memory fake.

You are not refactoring towards a diagram. You are buying the ability to change one thing without reading everything.

The read path after the change. Writes still land in the procedures on the right.

Two years on

Two years in, the boundary has held. The parts that broke were the ones where we let a controller reach past it because a deadline made the shortcut look cheap.

12 · Diagrams

Canvas · loops in view

For the posts where a paragraph cannot carry the idea. One canvas, the page palette, no colour except the signal for failure. It draws only while it is on screen and holds a single static frame under reduced motion.

Spec
ASPECT 16:7 · 200–320px TALL
LOOP 13s · 4 PHASES
PARTICLE 2.4px · TRANSIT 2.2s
DPR CAPPED AT 2
SKIPS DRAW WHEN OFFSCREEN
STATIC FRAME ON REDUCE
Reads the theme

The canvas pulls Ink, Faint, Rule and Signal straight off the root at paint time, so it follows the Dark and Light switch with no second palette to maintain.

INK · nodes, active queue
FAINT · idle strokes, labels
RULE · paths, capacity track
SIGNAL · overflow only
Rules

01  One idea per diagram. If it needs a legend, it needs splitting.

02  The loop must be readable from any entry point, with no start button.

03  Labels in JetBrains Mono at 10px, never smaller.

04  Always a caption. The diagram supports the prose, it does not replace it.
